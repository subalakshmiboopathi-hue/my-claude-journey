01 — The brain: system prompt design

The underlying Claude call is scoped to exactly one job: act as an ATS parsing engine plus an expert technical recruiter, and return structured JSON only — never prose — so the UI can render score dials, bars, and tag lists without any fragile text-scraping. Key design decisions:

  • Strict output contract. The prompt defines the exact JSON schema (verdict, overall_score, category scores, keyword matches/gaps, prioritized fixes) and instructs Claude to emit nothing else — no markdown fences, no preamble — so JSON.parse() never breaks.
  • Grounded scoring, not vibes. The prompt tells Claude to score based on concrete ATS behavior (keyword/skill overlap with the JD, standard section headers, parseable formatting signals described in text, quantified impact in bullets) rather than an impressionistic "does this feel good" judgment.
  • Edge-case handling built in: if the pasted text isn't a resume (e.g. random text, a poem, an empty paste), the model sets a flags.irrelevant_input field and returns a short explanatory message instead of fabricating a score. If no job description is given, it still scores formatting/structure/impact but skips keyword-gap analysis and says so.
  • Tone constraint. Friendly but direct — the prompt explicitly bans generic praise ("Great job!") and vague fixes ("improve your bullet points"), requiring every suggestion to name the exact line or section and show a rewrite.

You are an ATS parsing simulator and expert technical recruiter...
Score 4 categories: Keyword Match, Formatting & Parseability,
Impact & Metrics, Structure & Sections...
Return ONLY valid JSON matching this schema: { ... }
If input isn't a resume, set flags.irrelevant_input = true...

02 — Why this UI fits an ATS checker

The interface deliberately avoids a generic chat box. An ATS score is fundamentally a machine-reading concept, so the visual language leans into "scanning": a circular gauge for the score, a sweeping scan-line loading animation while the document is analyzed, and monospace type (JetBrains Mono) for anything numeric or machine-derived — score, keyword tags, priority labels — while human-authored copy stays in a humanist sans (Inter/Space Grotesk). The phosphor-green accent is a direct nod to terminal/scanner displays rather than a decorative color choice.

Keyword matches and gaps render as tags so overlap is scannable in one glance; fixes are collapsible cards ranked by priority dot (red/amber/blue) so a student can act on the top 2–3 items first instead of being overwhelmed by a wall of feedback.

03 — Extending this assistant

  • File upload: add a PDF/DOCX drop zone that extracts text client-side (e.g. pdf.js) before sending it as the resume field — the system prompt already accepts raw text, so no prompt change needed.
  • Multi-step flow: chain a second Claude call that takes the accepted fixes and regenerates a full revised resume draft, using the first response's JSON as input context.
  • Memory across sessions: store the last scan's JSON in the browser and let returning users diff their new score against their previous one ("+12 points since last scan").
  • Tool use: connect a live job-search MCP (e.g. Indeed) so a user can pick a real posting instead of pasting a JD, and batch-score their resume against several listings at once.
  • Coach mode: add a follow-up chat turn after the scan so users can ask "why is this bullet weak?" — reuse the same system prompt with an appended conversational-mode instruction.
